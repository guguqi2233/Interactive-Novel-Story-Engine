# v0.3 Release Notes

## Version Name

v0.3 - Trustworthy Local World Tick

## Version Goal

v0.3 upgrades the project from a persistent local interactive novel engine into a more trustworthy simulated world with structured NPC behavior, advanced deterministic actions, quest state, world tick processing, and local debug timeline tooling.

This remains a local self-use engine. It is not a hosted service, not a multiplayer system, and not a production game platform.

The LLM is still not the world judge. It parses intent, renders narration, and summarizes memories; the deterministic world engine remains the only source of truth for `GameState`, rules, events, and saves.

## New Features

### NPC Schedule Resolver

- NPCs can define schedule entries in `npcs.yaml`.
- Schedule entries support `time_of_day`, `location_id`, and `activity`.
- Schedule changes are emitted as `StateDelta`.
- Schedule changes run through world tick and are recorded as system events.
- Hidden NPCs remain filtered from player-visible state.

### Search Action

- Added `search` as a player action type.
- Search can reveal discoverable objects and discoverable facts.
- Search supports current location, object target, and NPC target scopes.
- Search consumes in-game time and records an Event through `GameLoop`.
- Failed search does not reveal hidden facts.

### Inventory Rules

- Item ownership is now structured through `location_id`, `owner_id`, and `container_id`.
- Inventory is derived from authoritative item ownership.
- Added inventory rules for:
  - `can_pick_up`
  - `pick_up_item`
  - `drop_item`
  - `has_item`
  - `get_inventory`
- Hidden items cannot be picked up before discovery.
- `visible_state.inventory` is generated by the backend.

Note: pickup/drop are rule functions in v0.3, not full natural-language action handlers.

### Lockpick Action

- Added `lockpick` action.
- Locked targets support:
  - `locked`
  - `lock_difficulty`
  - `lock_state`
- Outcomes include `success`, `partial_success`, `failure`, and `invalid`.
- Failure and partial success have consequences such as lock state changes or visible lock-mark facts.
- Lockpick uses deterministic rules and seeded RNG in tests.

### Sneak Action

- Added `sneak` action.
- Sneak checks target validity, location connectivity, cover, light, NPC alertness, and NPC suspicion.
- Sneak can move the player or modify NPC suspicion through `StateDelta`.
- Hidden observers can affect rule outcomes but are not named in player-visible facts.

### Quest State Machine

- Added structured quest loading from `quests.yaml`.
- Added `QuestState`, `QuestStage`, quest visibility/status, triggers, current stage, and completed objectives.
- Quest triggers can respond to:
  - fact discovered
  - item acquired
  - NPC talked
  - location visited
- Quest changes are represented as `StateDelta`.
- Hidden inactive quests do not appear in `visible_state`.

### World Tick

- Added lightweight world tick after successful or partially successful player actions.
- Tick currently handles:
  - NPC schedule resolution
  - NPC suspicion decay
  - delayed consequences
  - quest triggers caused by tick deltas
- Tick emits a system `Event` when it produces changes.
- Tick does not call LLM and is not passed to Narrator.

### Debug Timeline

- Added local debug endpoints:
  - `GET /debug/sessions/{session_id}/events`
  - `GET /debug/saves/{save_id}/events`
- Debug API is controlled by `ENABLE_DEBUG_API`.
- Timeline returns event metadata and `state_deltas`.
- Frontend Debug panel can display event timeline entries with expandable deltas.

Debug timeline is for local development only. It can expose raw internal deltas and must not be treated as player-facing narrative output.

### Integration Regression Tests

- Added v0.3 integration regression covering:
  - observe
  - search
  - inventory pickup rule
  - move
  - wait
  - NPC schedule tick
  - lockpick
  - sneak
  - talk
  - quest progression
  - save/load
  - event replay
  - debug timeline
  - memory summary non-mutation

## Behavior Changes

- `GameLoop` now runs quest trigger resolution after action deltas and before turn advancement.
- `GameLoop` runs `world_tick` after successful or partially successful actions.
- System tick changes are appended as `system` events with `action_type="world_tick"`.
- SQLite event persistence now stores per-save `sequence` to preserve EventLog order during save/load and replay.
- `apply_delta` validates Pydantic field types on `set`, so replayed JSON values convert back to model/enum types where possible.
- `visible_state.quests` can now contain known/active quests.
- `visible_state.inventory` is derived from item ownership.

## API Changes

### Game API

- `POST /game/start`
  - accepts optional `world_id`
  - defaults to `mist_valley`
  - returns `world_id` and structured `visible_state`

- `POST /game/input`
  - supports v0.3 action types through intent parsing:
    - `search`
    - `lockpick`
    - `sneak`
  - returns narrative text, suggested actions, turn, and `visible_state`

- `GET /game/state/{session_id}`
  - returns structured visible state including inventory, known facts, visible NPCs, visible objects, quests, time, and location

- `GET /game/saves`
  - lists local saves

- `POST /game/{session_id}/save`
  - saves state snapshot and event history

- `POST /game/load/{save_id}`
  - loads a save and creates/restores an active session

### Debug API

- `GET /debug/sessions/{session_id}/events`
- `GET /debug/saves/{save_id}/events`

These endpoints are local-debug only and gated by `ENABLE_DEBUG_API`.

## Content Pack Format Changes

### `npcs.yaml`

NPC definitions may include:

```yaml
schedule:
  - time_of_day: morning
    location_id: blacksmith
    activity: tending the cold forge
```

Schedule target locations are validated.

### `items.yaml`

Items support structured placement and interaction fields:

- `location_id`
- `owner_id`
- `container_id`
- `portable`
- `visible`
- `hidden`
- `discoverable`
- `discovered_by`
- `tags`
- `locked`
- `lock_difficulty`
- `lock_state`

Items must not have conflicting placement.

### `facts.yaml`

Facts remain first-class content pack data:

- `id`
- `text`
- `visibility`
- `known_by`
- `tags`

Visibility values:

- `public`
- `hidden`
- `discoverable`

### `quests.yaml`

Quests now use structured state machine data:

- `id`
- `title`
- `description`
- `initial_stage`
- `visibility`
- `stages`
- `triggers`

Stages include:

- `id`
- `title`
- `description`
- `objectives`
- `next_stages`

Triggers include:

- `type`
- `id`
- `action`
- optional `objective_id`
- optional `next_stage`

Supported trigger types:

- `fact_discovered`
- `item_acquired`
- `npc_talked`
- `location_visited`

## Known Limitations

- Inventory pickup/drop are rule functions, not complete natural-language action handlers.
- No combat.
- No economy/shop system.
- No crafting.
- No equipment or weight system.
- No pathfinding.
- No complex NPC planning.
- No LLM-driven autonomous NPC agents.
- No quest editor or full quest scripting language.
- No vector database memory.
- Debug API has no production authentication and must remain local-only.
- Debug timeline exposes raw `state_deltas` and can include hidden/system details.
- `ActionResult.reason` is passed to Narrator and must remain player-safe by convention.
- Memory summaries receive full event payloads but do not mutate `GameState`.

## Upgrade Notes from v0.2

1. SQLite schema adds `stored_events.sequence`.

   Existing local databases are migrated lazily by adding the column with default `0`. For clean local testing, deleting the old ignored `.db` file is also acceptable.

2. `visible_state.quests` is no longer always empty.

   Known/active quests now appear in player-visible state.

3. `visible_state.inventory` is derived from item ownership.

   Frontend or clients should not maintain their own inventory truth.

4. Content packs may need updated `quests.yaml`.

   v0.3 expects structured quest fields such as `title`, `initial_stage`, `stages`, `visibility`, and `triggers`.

5. NPC schedules are stored on NPC definitions.

   Invalid schedule locations now fail validation.

6. Debug API is separate from player API.

   Set `ENABLE_DEBUG_API=true` for local debugging. Disable it outside trusted local development.

7. LLM provider selection remains environment-driven.

   Use `LLM_PROVIDER=mock` for local development/tests. Use `LLM_PROVIDER=openai` only with `LLM_API_KEY` set in the environment.

## Recommended v0.4 Direction

1. Promote pickup/drop to first-class player action handlers.
2. Add narrator-safe reason constraints or tests.
3. Add trigger execution history for more complex quest graphs.
4. Add content-author documentation for hidden facts, discoverable objects, hidden NPCs, and quest visibility.
5. Add a filtered player-facing memory view if memory summaries become visible.
6. Consider defaulting the frontend Debug panel closed outside local development.
7. Expand either conflict/combat, richer NPC routines, or content authoring tools based on the next design priority.
